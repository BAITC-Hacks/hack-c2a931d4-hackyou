# TraceGraph

Локальное рабочее место аналитика для кейса HackAlem «Граф денег». Команда hackyou.

## Текущий этап

Работают FastAPI + React/TypeScript, локальная SQLite, создание и поиск кейсов, импорт parquet, проверка данных и история наборов. Анализ вызывает TraceGraph AI 0.3.0 отдельным процессом: доступны этапы выполнения, отмена, история запусков, Top-20, распределение ролей и скачивание девяти файлов снимка. Граф, подробные карточки и AI-расследования пока не выведены в веб-интерфейс. SDK также предоставляет три локальных агента обогащения расследований; их досье пока не выведено в веб-интерфейс.

## Установка

Требуются Python 3.11+ и Node.js 22.12+ (или 24 LTS).

Windows PowerShell, из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
python -m venv .venv-engine
.\.venv-engine\Scripts\python.exe -m pip install -r ml\requirements-lock.txt
.\.venv-engine\Scripts\python.exe -m pip install -e ./ml --no-deps
npm.cmd --prefix frontend ci
```

Если команда python открывает Microsoft Store, используйте полный путь к установленному Python для первой команды. Активация окружения не требуется.

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
python3 -m venv .venv-engine
.venv-engine/bin/python -m pip install ./ml
npm --prefix frontend ci
```

## Запуск одной командой

```powershell
.\.venv\Scripts\python.exe scripts\dev.py
```

Linux/macOS: .venv/bin/python scripts/dev.py

- Приложение: http://127.0.0.1:5173
- OpenAPI: http://127.0.0.1:8000/docs
- Проверка backend: http://127.0.0.1:8000/api/v1/health

Ctrl+C останавливает оба сервера. Порты 8000 и 5173 должны быть свободны. Локальные серверы слушают только loopback; доступ из сети не включён.

SQLite создаётся автоматически в storage/tracegraph.db, миграции применяются при запуске. Отдельный сервер БД или Docker не нужен. Каталог storage исключён из Git. Настройки доступны в .env.example; относительный путь хранилища считается от корня проекта.

Движок имеет отдельное окружение: его lock-файл использует другую версию pyarrow, поэтому не устанавливайте оба requirements в одну venv. Windows lock включает CPU PyTorch. На Linux/macOS базовая установка без torch использует штатный Isolation Forest fallback; для Autoencoder установите совместимый CPU PyTorch по официальной инструкции. Фактическая модель и причина fallback показываются в результате. Мост использует исходники ml/src; после обновления ветки новая версия применяется к новым запускам.

Настройки: TRACEGRAPH_ENGINE_PYTHON — другой интерпретатор; TRACEGRAPH_ENGINE_MODEL — auto/autoencoder/isolation_forest; TRACEGRAPH_ANALYSIS_TIMEOUT_SECONDS — общий лимит процесса, по умолчанию 300 секунд, включая импорты. Одна локальная очередь выполняет по одному анализу. Для каждого каталога storage разрешён один API worker; запускайте без --workers. История сохраняется при закрытии браузера. После остановки API незавершённый запуск отмечается «Прерван» и требует явного нового запуска.

## Первый пользовательский сценарий

1. Нажмите «Новый кейс», задайте название и необязательное описание.
2. Выберите nodes.parquet, edges.parquet и transactions.parquet из одной выгрузки.
3. Нажмите «Проверить и сохранить». При ошибке исходный кейс сохраняется, а некорректный набор не публикуется.
4. Просмотрите размеры сети, период, оборот и ограничения данных.
5. Нажмите «Запустить анализ» ниже отчёта. Следите за фактическими этапами; при необходимости отмените запуск.
6. Изучите Top-20 и скачайте обязательные CSV или JSON-снимок. Роли и приоритеты выдаёт движок; оценки не являются вероятностью нарушения.
7. Вернитесь к истории или обновите страницу: кейс, набор и результаты остаются доступны. Повторная загрузка создаёт новый набор; предыдущий доступен через переключатель. Новый анализ создаёт отдельный запуск.

Готовые выгрузки друга можно загрузить через «Загрузить готовые CSV»: nodes_roles.csv, clusters.csv и top_nodes.csv. Они сверяются с выбранным набором и сохраняются как отдельный запуск. Ручной импорт трёх CSV не содержит полный SDK-снимок и не подменяет запуск движка.

Набор со статусом «Данные проверены» ещё не проходил AML-анализ. Этот статус означает только успешную техническую проверку входных файлов.

Ожидаемые обязательные колонки:

| Файл | Поля |
|---|---|
| nodes.parquet | gid, depth, is_seed |
| edges.parquet | src, dst, sum_kzt, n_tx, depth |
| transactions.parquet | src, dst, date, sum_kzt |

Идентификаторы — целые int64, is_seed — boolean, суммы — конечные положительные числа с точностью до двух знаков, даты — Parquet date/timestamp или ISO-строки. Дополнительные поля сохраняются в оригинальных файлах. Повторяющиеся строки транзакций не удаляются. Проверяются суммы и количество операций для каждой пары src/dst; изолированные клиенты сохраняются.

По умолчанию лимит одного файла — 50 МБ и одного исходного parquet — 1 000 000 строк. Это ограничения импорта, а не обещание производительности анализа на миллионе узлов. Размер официального набора не захардкожен. Даты отображаются в календарной дате источника; приложение не предполагает неизвестный часовой пояс.

API текущего этапа: POST/GET /api/v1/cases, GET /api/v1/cases/{id}, POST /api/v1/cases/{id}/datasets, GET /api/v1/datasets/{id}, GET /api/v1/datasets/{id}/quality. При multipart-загрузке поля называются nodes, edges, transactions.

## Границы проверки

Тесты API покрывают импорт, сохранение после пересоздания приложения, согласованность CSV, ошибки, отмену, защиту от повторного запуска, прерывание, контрольные суммы и точные int64. Тесты процессного адаптера проверяют остановку дочернего процесса по отмене/таймауту. backend/tests/test_engine_integration.py использует данные из data/, запускает реальный SDK, проверяет все девять загрузок и повторное открытие результата; при отсутствии .venv-engine этот тест пропускается. Это проверка интеграции, а не качества AML-гипотез.

После аварийного завершения процесса между записью файлов и фиксацией SQLite возможен неиспользуемый каталог. Незавершённые запуски получают статус «Прерван» при старте; автоматического возобновления нет. Незавершённые выгрузки недоступны для скачивания. Штатные ошибки очищают временные файлы; автоматическая очистка всех каталогов после аварийного завершения ещё не реализована. Диагностика процесса хранится в storage/cases/{case_id}/analyses/{analysis_id}/engine.log.
