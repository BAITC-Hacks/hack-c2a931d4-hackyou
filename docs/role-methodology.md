# Методика ролей, уверенности и приоритета

Движок строит гипотезы о **наблюдаемой** структуре переводов. Ролевой разметки нет, поэтому здесь нет обученного классификатора ролей, role accuracy, вероятности нарушения закона или утверждений о виновности. Все коэффициенты — прозрачные начальные эвристики. Аномальная модель влияет только на приоритет проверки.

## Признаки и нормализация

Основной граф направлен; деньги идут `src → dst`. Для рангов используются `in_degree`, `out_degree`, `in_kzt`, `out_kzt`, `in_tx`, `out_tx`, `pagerank`, `betweenness`, `downstream_reach`, `seed_reach_count`, `cluster_bridge_score`.

Для положительного значения `x` относительный ранг `P(x) = (L + (E − 1)/2)/(N − 1)`, где `L` — число меньших значений, `E` — число равных. Нулевые, отрицательные значения, выборки менее двух узлов и константные распределения дают сигнал 0. Ранг находится в `[0,1]`. Если на глубине узла есть минимум 20 узлов и минимум 3 различных значения признака, итоговый ранг равен `0.65 × P_всех + 0.35 × P_той_же_глубины`; иначе используется глобальный ранг. Денежная сумма не интерпретируется как вероятность.

Обозначения:

- `I = .65 P(in_kzt) + .35 P(in_tx)`, `O = .65 P(out_kzt) + .35 P(out_tx)` — входящий и исходящий поток с учётом частоты.
- `S = (.7 P(seed_reach_count) + .3 seed_convergence_score) × min(seed_reach_count/2, 1)` — сходимость seed. Единственная lineage не равна сходимости нескольких ветвей.
- `T = (P(pagerank) + P(betweenness))/2`, `H = min(I,O)`.
- `B = .5 P(cluster_bridge_score) + .5 cluster_bridge_score`.
- `D_in = min(in_degree/max(in_tx,1),1)`, `D_out = min(out_degree/max(out_tx,1),1)` — доля различных контрагентов среди переводов.
- `Q = max(0, 1 − |ln(out/in)|/ln(3))` при положительном наблюдаемом балансе; для отношения 0 — 0. Для seed или отсутствующего баланса `Q` недоступен.
- `R` — `rapid_pass_through_score`, `F_in` / `F_out` — синхронность входа/выхода. Для seed `R` недоступен.
- `J` — `temporal_coordination_score`: совместимый по датам входящий/исходящий эпизод с учётом сумм и неопределённости одного дня.
- `C` — измеренный counterfactual disruption; до вычисления — 0, отдельный статус `not_computed`.

Недоступный баланс, retention или временной проход исключаются из соответствующей взвешенной суммы; веса оставшихся сигналов нормируются заново. Пропуск не превращается в наблюдаемый ноль. Counterfactual до измерения остаётся консервативным нулевым вкладом; отсутствие измерения сохраняется отдельно.

## Роли

Ниже указаны начальные веса. Переопределение `config.role_weights[role][signal_name]` заменяет указанные веса и сохраняет остальные; после замены сумма нормируется. Неизвестные роли/сигналы и некорректные веса отклоняются. Точные имена — в `DEFAULT_ROLE_WEIGHTS` модуля `inference.py`.

| Роль | Допуск | Сила гипотезы |
|---|---|---|
| consolidator | минимум 2 отправителя, положительный вход | `.25 P(in_degree) + .20 I + .35 S + .10 D_in + .10 T` |
| transit | есть вход и выход, оба объёма положительны | `.35 Q + .30 R + .20 P(betweenness) + .15 H` |
| distributor | минимум 2 получателя, положительный выход | `.30 P(out_degree) + .20 P(out_kzt) + .15 P(out_tx) + .20 F_out + .10 P(downstream_reach) + .05 D_out` |
| terminal | есть положительный вход, исходящих связей 0, узел не на границе глубины | `.55 × 1 + .25 retention_ratio + .20 I` |
| coordinator | минимум 2 достижимых seed, положительные вход и выход, есть betweenness-сигнал или мост между сообществами | `.25 S + .20 P(betweenness) + .10 P(pagerank) + .15 B + .10 H + .10 C + .10 J` |
| peripheral | ни одна допустимая роль не достигает порога | `1 − максимум силы допустимых непериферийных ролей` |

Недопустимая роль имеет score 0. Все шесть scores сохраняются. По умолчанию порог `role_threshold=.45`; для coordinator используется `.45+.15=.60` (с ограничением сверху 1). Формулировка coordinator всегда означает кандидата в узлы координации. Среди допустимых ролей выше порога побеждает максимальный score, равенство разрешается фиксированным порядком `consolidator, transit, distributor, terminal, coordinator`. Изолированный узел получает peripheral.

`secondary_role` — следующая допустимая непериферийная гипотеза с ненулевой силой. `role_ambiguity=true`, если разность сил основной/вторичной гипотез не превышает `.08`; у peripheral также отмечается ближайшая к порогу гипотеза в диапазоне `[threshold−.08, threshold)`. Настройка `ambiguity_margin` заменяет `.08`.

## Независимые группы и уверенность

Несколько коррелирующих метрик не считаются несколькими независимыми подтверждениями: степени, суммы, частоты и баланс относятся к одной flow-группе. Вклад counterfactual не создаёт независимую от topology группу уверенности. Аномальность не входит в confidence.

| Роль | Используемые группы поддержки |
|---|---|
| consolidator | flow=`mean(P(in_degree),I)`; seed=`S`; topology=`T`; temporal=`F_in` |
| transit | flow=`mean(доступные Q,H)`; topology=`P(betweenness)`; temporal=`R`, если доступен |
| distributor | flow=`mean(P(out_degree),O)`; topology=`P(downstream_reach)`; temporal=`F_out` |
| terminal | flow=1, наблюдаемые вход и отсутствие выхода |
| coordinator | flow=`H`; seed=`S`; topology=`T`; community=`B`; temporal=`J` |
| peripheral | flow=`role_strength`, кроме изолированного узла: 0 |

Группа поддерживает гипотезу при значении ≥`.45`. `coverage=min(число поддерживающих групп/4,1)`, `agreement` — среднее доступных значений групп, `sample=min(ln(1+in_tx+out_tx)/ln(21),1)`.

`confidence = (.18 + .27 role_strength + .25 coverage + .15 agreement + .15 sample) × (.35 + .65 observability_score)`.

Затем применяются ограничения: при ambiguity умножение на `.78`, для seed на `.90`; на границе глубины уверенность не выше `.45`, для изолированного узла не выше `.35`. Величины ограничены `[0,1]`. Метки: `high ≥.75`, `medium ≥.45`, иначе `low`.

`role_strength` — сила ролевой гипотезы. `confidence` — эвристическая надёжность с учётом наблюдаемости, неоднозначности и подтверждений. `role_score` в официальном CSV отображает **confidence**; strength остаётся отдельным полем JSON. Это намеренное разделение, эти значения не взаимозаменяемы.

## Приоритет проверки

Нормированные `priority_components`:

| Компонент | Значение | Вес |
|---|---|---:|
| seed_convergence | `S` | .30 |
| structural_importance | `T` | .20 |
| flow_significance | `max(I,O)` | .20 |
| role_strength | сила роли; для peripheral сила ×`.15` | .15 |
| anomaly_score | оценка ML, если модель выполнилась | .10 |
| cluster_bridge | `B` | .05 |

`base = Σ(weight × component)/Σ(weight)` по доступным компонентам. Отсутствующая anomaly имеет JSON `null`, её вес исключается; нулевой anomaly score означает измеренный нулевой сигнал и сохраняет вес.

`priority_modifier=(.55+.45 confidence) × (.65+.35 observability_score)`; `priority_score=base × priority_modifier`. `compute_priority()` повторяет эту формулу для анализа устойчивости весов. Уверенность в peripheral не должна сама поднимать AML-приоритет, поэтому соответствующий компонент уменьшен. При равном приоритете `rank_nodes()` использует точный целочисленный `gid`, без преобразования к float.

При полном анализе counterfactual считается для предварительных top-N; повторный расчёт ролей/приоритета использует результаты измерения. Это направленная дополнительная проверка предварительно отобранных узлов, а не равномерно доступный всему графу сигнал. Для остальных узлов глобального анализа сохраняется `not_computed`. Ветка расследования может измерить удаление любого выбранного узла. Если такое измерение новое, ролевые оценки и confidence ветки пересчитываются с нормализацией на полном исходном наборе узлов. Исходные карточки и глобальный рейтинг сохраняются; повторное рассмотрение имеющегося counterfactual не добавляет уверенности.

## Связанные временные эпизоды

Самостоятельные пики входа и выхода `F_in/F_out` характеризуют соответствующее направление. Для координации используется `J`: входящие и исходящие события должны помещаться в одно окно с допустимой разницей дат `0..temporal_window_days`. При стандартном окне два дня вход 1 июля и выход 20 июля не дают положительного `J`.

Для окна алгоритм FIFO распределяет наблюдаемый вход по совместимому по датам выходу; каждая сумма в тиынах используется не более одного раза в рамках этого расчёта. Совместимая сумма делится на максимум сумм входа/выхода на участвующих днях. Разнообразие равно минимуму сигналов синхронности участвующих отправителей и получателей. `J` для эпизода — произведение разнообразия, совместимости сумм и `1 − .5 × доля совместимой суммы в тот же день`. Последний множитель снижает поддержку там, где неизвестна очередность внутри дня. Итоговый `J` — максимальный сигнал эпизода.

В карточке сохраняются пять сильнейших `temporal_episodes`: даты, совместимые суммы, источники/получатели и технические ссылки на операции. Для большого эпизода ссылки ограничены 200 операциями и 100 контрагентами каждого направления; обрезка и полные количества указаны явно. Окна могут пересекаться, поэтому их суммы нельзя складывать. Распределение сумм — воспроизводимая проверка совместимости, а не установление происхождения конкретных средств. Ссылки относятся ко всем операциям на участвующих днях, не к доказанному попарному соответствию переводов.

## Evidence и ограничения данных

Каждый узел получает числовое описание фактического входа/выхода и объяснение гипотезы. Evidence имеет стабильный ID `E-{gid}-{type}`, источник, значение, группу и тип: observation / inference / limitation. Объяснения высокого ранга приводят фактическую величину и относительный сигнал; отсутствие сильных доказательств не заменяется вымышленными. Короткое `why` ограничено 200 символами. Количество evidence не используется вместо числа независимых групп.

`explain_node()` связывает evidence с наблюдаемыми операциями и ограниченным набором путей от seed. Ветка добавляет целевые расчёты с ID `I-{gid}-{action}`. [Разбор с аналитиком](analyst-review.md) сохраняет реальные отзывы о полезности и расхождениях ролей, не заполняя отсутствующую разметку и не меняя веса автоматически.

Четырёхшаговый обход по исходящим не покрывает всю сеть. Узел на глубине `max_depth` без исходящих не получает terminal только на основании этой границы. Вход seed неполон, поэтому его out/in и временной проход не используются при определении роли. Даты имеют дневную точность: совпадение входа/выхода за 0–2 дня не доказывает последовательность внутри дня или движение тех же денежных средств. В выгрузке отсутствуют внешнебанковские переводы и операции ниже порога сбора; наблюдается только один месяц. Результаты описывают текущую выборку.
