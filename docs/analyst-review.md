# Разбор результатов с аналитиком

Движок формирует до 30 случаев для предметной проверки ролей, объяснений и полезности приоритетов. Размеченных исходов в исходном пакете нет. Шаблон создаётся с пустыми полями аналитика; уверенность движка остаётся эвристической оценкой.

## Подготовка

После экспорта анализа выполните из корня репозитория:

```powershell
.\.venv\Scripts\python.exe ml/examples/review_results.py --analysis out --output out-review
```

Пример загружает сохранённую сессию через `TraceGraph.load_analysis()` и не обучает модель повторно. Создаются `analyst_review.csv` и `review_packet.json`. Повторная команда не перезаписывает существующие файлы: для нового разбора выберите другую папку.

Выборка детерминирована: по очереди берётся ещё не выбранный узел из групп приоритетных, неоднозначных, находящихся на границе наблюдения, периферийных и аномальных. В периферийной группе выбираются узлы около её медианного приоритета. Это сравнительная группа, её участники не считаются заранее нормальными. При малом лимите не все группы обязательно попадут в выборку. JSON содержит причины выбора и все `gid` строками.

При импорте CSV в Excel задайте тип колонки `gid` как **текст**: автоматическое открытие способно округлить 18-значные идентификаторы. Для программной интеграции читайте CSV стандартным `csv.DictReader`, либо используйте JSON. Округлённые, неизвестные и повторяющиеся идентификаторы при проверке отклоняются.

## Что заполнять

Для каждого узла просмотрите карточку и подтверждение через `engine.explain_node(gid)`. Зафиксируйте один `analyst_disposition`:

| Значение | Смысл |
| --- | --- |
| `useful` | Приоритизация и объяснение дают полезное основание продолжить разбор. |
| `disputed` | Вывод или объяснение спорны; запишите причину. |
| `ordinary` | Наблюдаемое поведение получило обычное объяснение и не требует приоритетного разбора. |
| `insufficient_data` | Для содержательной оценки данных недостаточно. |
| Пусто | Случай ещё не просмотрен. |

В `analyst_role` можно указать альтернативную роль: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`. Она необязательна, но требует заполненного `analyst_disposition`. В `analyst_notes` укажите конкретные операции, альтернативное объяснение и недостающие сведения. Изменять машинные колонки не требуется: расчёт отчёта всё равно берёт роль и ранг из исходного анализа. `analysis_id` и `result_fingerprint` связывают отзыв с точной версией результата.

## Отчёт

```powershell
.\.venv\Scripts\python.exe ml/examples/review_results.py --analysis out --filled-csv out-review/analyst_review.csv --output out-review
```

`review_summary.json` содержит число просмотренных и пустых случаев, распределение ответов, расхождения ролей, группы эвристической уверенности и отдельную сводку по исходному Top-20. Для другого N задайте `--top-n`.

`usefulness_precision_on_assessable` равен `useful / (useful + disputed + ordinary)` среди фактически размеченных случаев. Пустые строки и `insufficient_data` исключаются из знаменателя и показываются отдельно. В Top-N дополнительно указывается доля узлов с заполненной меткой. Без меток значение равно `null`. Это описательная полезность на рассмотренной части намеренно неоднородной выборки; она не оценивает точность выявления нарушений на всей популяции и не калибрует вероятность виновности.

Отчёт также пересчитывает **только готовый итоговый рейтинг** с нулевым весом аномальности и перенормированными остальными весами. Показывается пересечение Top-N и перемещение исходных лидеров. Признаки, роли, уверенность и набор ранее рассчитанных counterfactual остаются фиксированными. Это проверка чувствительности компонента ранжирования, а не полный эксперимент без модели и не доказательство её полезности.

Сначала разбирайте причины повторяющихся расхождений: ошибки временной связности, границы наблюдения, смешение ролей, слабое объяснение. Изменения весов вносите отдельно и сравнивайте новую версию на новых рассмотренных случаях. Импорт отзыва автоматически не меняет параметры движка. Сохраняйте исходные отзывы и версию анализа, чтобы улучшения можно было проверить.

## Python API

```python
from tracegraph_ai import TraceGraph
from tracegraph_ai.review import create_review_cases, export_review_template, summarize_review

engine = TraceGraph.load_analysis("out")
analysis = engine.get_analysis()
cases = create_review_cases(analysis, limit=30)
files = export_review_template(analysis, "out-review")
# После заполнения CSV аналитиком:
report = summarize_review(files["csv"], analysis, top_n=20)
```

Функции не изменяют анализ. Неверные метки, другая версия результата и испорченные идентификаторы приводят к `InputValidationError`.
