# TraceGraph

Локальное рабочее место аналитика для кейса HackAlem «Граф денег». Команда hackyou.

## Текущий этап

Работают FastAPI + React/TypeScript, локальная SQLite, создание и поиск кейсов, импорт трёх parquet-файлов, проверка данных и просмотр сохранённых наборов. ML-движок, граф, роли и AI-агент пока не подключены. Их интеграция — следующий этап; каталог ml принадлежит разработчику движка.

## Установка

Требуются Python 3.11+ и Node.js 22.12+ (или 24 LTS).

Windows PowerShell, из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd --prefix frontend ci
```

Если команда python открывает Microsoft Store, используйте полный путь к установленному Python для первой команды. Активация окружения не требуется.

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
```

## Запуск одной командой

```powershell
.\.venv\Scripts\python.exe scripts\dev.py
```

Linux/macOS: .venv/bin/python scripts/dev.py

- Приложение: http://127.0.0.1:5173
- OpenAPI: http://127.0.0.1:8000/docs
- Проверка backend: http://127.0.0.1:8000/api/v1/health

Ctrl+C останавливает оба сервера. Порты 8000 и 5173 должны быть свободны. Локальные серверы слушают только loopback; доступ из сети не включён.

SQLite создаётся автоматически в storage/tracegraph.db, миграции применяются при запуске. Отдельный сервер БД или Docker не нужен. Каталог storage исключён из Git. Настройки доступны в .env.example; относительный путь хранилища считается от корня проекта.

## Первый пользовательский сценарий

1. Нажмите «Новый кейс», задайте название и необязательное описание.
2. Выберите nodes.parquet, edges.parquet и transactions.parquet из одной выгрузки.
3. Нажмите «Проверить и сохранить». При ошибке исходный кейс сохраняется, а некорректный набор не публикуется.
4. Просмотрите размеры сети, период, оборот и ограничения данных.
5. Вернитесь к истории или обновите страницу: кейс и отчёт остаются доступны. Повторная загрузка создаёт новый набор; предыдущий доступен через переключатель.

Набор со статусом «Данные проверены» ещё не проходил AML-анализ. Этот статус означает только успешную техническую проверку входных файлов.

Ожидаемые обязательные колонки:

| Файл | Поля |
|---|---|
| nodes.parquet | gid, depth, is_seed |
| edges.parquet | src, dst, sum_kzt, n_tx, depth |
| transactions.parquet | src, dst, date, sum_kzt |

Идентификаторы — целые int64, is_seed — boolean, суммы — конечные положительные числа с точностью до двух знаков, даты — Parquet date/timestamp или ISO-строки. Дополнительные поля сохраняются в оригинальных файлах. Повторяющиеся строки транзакций не удаляются. Проверяются суммы и количество операций для каждой пары src/dst; изолированные клиенты сохраняются.

По умолчанию лимит одного файла — 50 МБ и одного исходного parquet — 1 000 000 строк. Это ограничения импорта, а не обещание производительности анализа на миллионе узлов. Размер официального набора не захардкожен. Даты отображаются в календарной дате источника; приложение не предполагает неизвестный часовой пояс.

API текущего этапа: POST/GET /api/v1/cases, GET /api/v1/cases/{id}, POST /api/v1/cases/{id}/datasets, GET /api/v1/datasets/{id}, GET /api/v1/datasets/{id}/quality. При multipart-загрузке поля называются nodes, edges, transactions.

## Границы проверки

Автоматические проверки используют синтетические parquet. Они покрывают сохранение после пересоздания приложения, несогласованные суммы и количества, ошибочные ссылки, повреждённые файлы, лимиты загрузки, несколько независимых кейсов, изолированные узлы и точные int64. Настоящие данные хакатона и AML-результаты пока не проверены.

После аварийного завершения процесса между записью файлов и фиксацией SQLite возможен неиспользуемый каталог; в историю кейсов он не попадает. Автоматическая очистка после аварийного завершения и восстановление заданий будут добавлены с worker. Штатные ошибки импорта откатываются и очищаются.
